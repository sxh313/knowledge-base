# 知屿 UI 设计审计与优化建议

## 1. 审计结论

本次检查覆盖以下主要页面和公共控件：

- 文档
- 收集箱
- AI 问答
- 复习教练
- Agent 整理
- 学习目标
- 统计
- 标签
- 设置
- 下拉菜单、展开按钮、卡片、空状态和响应式布局

当前整体判断：

- 界面完成度约为 70%。
- “AI 模板感”约为 35%。
- 夜间模式配色已经得到明显改善。
- 当前主要问题是控件体系不统一、圆角尺寸混乱、页面结构重复，以及中等宽度下的内容挤压。

## 2. 原生下拉菜单问题

当前“联网模式”等菜单使用的是原生 `<select>`。展开后的选项面板由 Windows 或浏览器负责渲染，不属于普通 HTML 弹层，因此即使关闭状态的输入框具有圆角，展开菜单仍然可能出现：

- 四角完全方正。
- 使用系统默认蓝色选中背景。
- 字体、内边距与应用不一致。
- 没有打开和关闭动画。
- 无法完整控制阴影、边框和选项圆角。
- 在不同操作系统上呈现不同效果。

单纯为 `<select>` 增加 `border-radius` 无法解决展开菜单的问题，需要将其替换成应用自己的弹层组件。

### 2.1 需要替换的原生下拉菜单

当前共有 6 处同类控件：

- AI 问答：知识库回答模式。
- AI 问答：联网搜索模式。
- Agent：回答详细程度。
- Agent：任务意图模式。
- 收集箱：分类选择。
- 文档列表：排序方式。

### 2.2 可复用的现有实现

项目中已经存在表现较好的自定义选择器：

- 设置页 `SettingsSelect`。
- AI 问答中的知识范围菜单。
- 模型角色绑定菜单。

建议将这些实现收敛为一个通用 `Select` 组件，而不是继续保留多套下拉菜单。

### 2.3 统一下拉菜单规范

- 桌面工具栏触发器高度：32px。
- 普通表单触发器高度：40px。
- 触发器圆角：9px。
- 弹层圆角：12px。
- 选项圆角：8px。
- 弹层内边距：6px。
- 选项高度：36–40px。
- 打开动画：120–160ms。
- 打开时箭头旋转 180°。
- 当前项使用紫色淡底和勾选图标。
- 支持上、下方向键、Enter 和 Esc。
- 靠近窗口底部时自动向上展开。
- 使用 Portal 或浮层定位，避免被父容器裁切。
- 桌面端使用自定义弹层；触摸设备可以按需要保留原生选择器。

## 3. 圆角系统问题

当前代码同时使用了以下圆角：

- `rounded`：4px。
- `rounded-sm`。
- `rounded-md`：6px。
- `rounded-lg`：8px。
- `rounded-xl`：12px。
- `rounded-2xl`：16px。
- `rounded-full`。
- 自定义 `0.65rem`、`0.9rem` 和 `1rem`。
- 主题变量中的 6px、9px、14px 和 20px。

TSX 中约有 237 个圆角类引用，并存至少六种普通圆角尺寸。这是部分按钮圆滑、部分按钮生硬的主要原因。

### 3.1 建议保留的圆角层级

- 小型标签、紧凑菜单项：6px。
- 按钮、输入框：9px。
- 下拉弹层、工具栏：12px。
- 主要卡片、模态框：16px。
- 999px 只用于状态标签、开关和真正的胶囊按钮。

建议在 `tailwind.config.js` 中将 Tailwind 圆角映射到主题变量，避免 `rounded-lg` 和 `--radius-lg` 表示两个不同尺寸。

## 4. 展开和折叠控件

### 4.1 当前表现较好的控件

- AI 知识范围菜单。
- 设置页自定义选择器。
- 模型角色绑定菜单。
- 富文本编辑器“更多工具”。

### 4.2 需要统一的控件

- 编辑器“导出”菜单缺少完整的 `aria-expanded`、选中状态和统一菜单项圆角。
- 引用来源展开按钮缺少 `aria-expanded`。
- Agent“依据”展开按钮缺少完整展开语义。
- 文档树分类按钮没有明确的展开状态。
- 文档大纲折叠按钮缺少状态说明。
- 编辑器工具栏显示和隐藏按钮只有箭头，缺少状态文本或无障碍说明。
- 部分弹层使用 `rounded-lg`，部分使用 `rounded-xl`，阴影和内边距不一致。

### 4.3 建议建立的公共组件

- `Select`：单选菜单。
- `DropdownMenu`：导出、更多操作等命令菜单。
- `Disclosure`：折叠内容、依据、分类树和设置分组。

通过公共组件统一箭头、圆角、动效、键盘操作、焦点状态和无障碍语义。

## 5. AI 模板感来源

### 5.1 重复使用英文大写眉题

当前多个页面使用了相同的结构：英文大写眉题、中文大标题、说明文字。例如：

- `YOUR NEXT MOVE`
- `CAPTURE NOW, ORGANIZE LATER`
- `MAKE PROGRESS VISIBLE`
- `YOUR LEARNING PULSE`
- `ORGANIZE YOUR LIBRARY`
- `WORKSPACE PREFERENCES`

这种结构是当前常见的 AI 生成界面特征。

建议：

- 大部分页面直接移除英文眉题。
- 必须保留时改成有实际信息价值的中文状态，例如“今日航线”或“待整理 3 项”。
- 不要让所有页面都使用完全相同的标题结构。

### 5.2 大圆角卡片嵌套过多

当前常见结构为：

```text
页面
└─ 大圆角卡片
   └─ 小圆角卡片
      └─ 圆角图标容器
```

这会让页面显得像由通用组件模板拼装而成。

建议：

- 让页面背景直接承载主要内容。
- 只有需要明确分组或悬浮的区域才使用卡片。
- 搜索、工具栏和任务列表优先通过分隔线和间距建立层级。
- 减少“卡片里面继续放三张卡片”的结构。

### 5.3 空状态重复

收集箱、Agent、标签和学习目标都使用了“大虚线框、紫色方形图标、两行文字”的相似空状态。

建议：

- 收集箱：显示可粘贴示例和“从剪贴板导入”。
- Agent：显示最近可执行任务，而不是只放机器人图标。
- 标签：展示推荐标签或未分类文档入口。
- 学习目标：展示轻量的示例目标。
- 不要让所有空状态都使用虚线框。

### 5.4 图标容器重复

紫色半透明圆角方块同时出现在品牌标志、Hero、空状态和快捷入口中，使用频率过高。

建议只保留一处作为“知屿”的核心识别符号。普通操作图标取消背景盒，直接使用线性图标。

## 6. 逐页优化建议

### 6.1 文档页

当前问题：

- “多选、今日笔记、模板”等按钮在中等宽度下逐字换行。
- 今日任务卡片内部文字被压得很窄。
- 顶部工具栏信息过多。
- “新建”按钮被拆成两行。

优化建议：

- 所有工具栏按钮增加 `white-space: nowrap`。
- 中等宽度下只保留图标，文字放入 Tooltip。
- 次要操作收进“更多”菜单。
- 今日任务卡片由三列改为两列或纵向列表。
- 保持“新建”文字单行显示。
- 降低文档卡片的圆角和垂直高度，提升内容密度。

### 6.2 AI 问答

当前问题：

- “知屿 AI”和 Hero 标题层级重复。
- 三张等宽快捷卡片较为模板化。
- 底部连续四个带边框控件显得较重。
- 输入区和页面中央之间存在大量空白。

优化建议：

- 只保留一个主标题。
- 将三张快捷卡改成紧凑的推荐问题列表。
- 将回答模式、模型和联网模式放入统一工具栏。
- 非常用设置收进“回答设置”菜单。
- 为输入框提供更多水平空间。
- 发送按钮启用时提供更明确的主色反馈。

### 6.3 复习教练

当前问题：

- Hero 右侧巨大装饰圆具有明显的通用模板感。
- 输入框、分钟数、日期和按钮被挤在同一行。
- “每日 30 分钟、新会话”等文字关系不清楚。

优化建议：

- 移除右上角装饰圆。
- 将表单改为两行布局。
- 把“每日学习时间”设计成完整表单字段。
- 将“新会话”改成明确的开关或独立按钮。
- 今日任务、掌握度和预算使用不同的信息密度，不要全部做成同等大卡片。

### 6.4 Agent

当前问题：

- 左侧历史区占用宽度较大。
- 主区域空状态过于空旷。
- 底部工具栏信息密度较高，但字体较小。
- 存在不利于长期阅读的 10px 文本。
- 权限、Skills、运行记录和模式选择缺少主次关系。

优化建议：

- 默认缩窄历史侧栏。
- 在空状态中直接提供三项可执行任务。
- 将权限、Skills 和运行历史放入“工作区”菜单。
- 正文字号最低保持 12px，主要控件最低保持 13px。
- 底部输入区只保留模式、附件和发送三个一级操作。

### 6.5 学习目标

当前问题：

- 横向表单在中等宽度下明显拥挤。
- 时间输入和日期缺少视觉标签。
- 空状态面积过大。

优化建议：

- 标题和时间放在第一行，日期和创建按钮放在第二行。
- 使用显式字段标签，不要只依赖 placeholder。
- 在空状态中提供“创建每日 30 分钟学习目标”示例按钮。

### 6.6 统计

当前问题：

- 三张指标卡形成“两张加一张”的不平衡布局。
- 卡片右下角装饰圆具有常见 SaaS 模板感。
- 夜间模式下活动热力图对比度偏低。

优化建议：

- 将三个指标改为一行紧凑数据条或统一三列。
- 删除装饰圆。
- 把主要空间留给活动热力图和分类分布。
- 空数据区域明确说明如何产生数据。

### 6.7 标签

当前问题：

- 页面大部分空间被空状态占据。
- “筛选标签”和“新建文档”关系不强。
- 英文眉题缺少实际信息价值。

优化建议：

- 没有标签时展示未分类文档。
- 提供常用标签建议。
- 新建文档不应成为该页面最强的一级操作。
- 将标签创建和标签管理作为主要动作。

### 6.8 设置

当前问题：

- 服务卡片右侧的状态、开关和展开按钮相互挤压。
- “收起配置”等文字会在狭窄区域断行。
- 设置区块全部纵向堆叠，扫描效率较低。
- 英文眉题仍然具有模板感。

优化建议：

- 服务卡片头部改为三列：名称、状态、开关与展开操作。
- 开关与“配置服务”不要挤在同一窄列。
- 高频设置保持展开，低频设置使用折叠分组。
- API 地址、模型和同步等区域使用统一表单间距。

## 7. 色彩和字体优化

新夜间模式已经明显改善，但紫色仍同时承担品牌、选中、按钮、图标、Hero 和空状态等过多角色。

建议的颜色分工：

- 紫色：当前页面和主要操作。
- 冰蓝：同步、联网和信息。
- 杏橙：复习、待处理和提醒。
- 薄荷绿：完成和连接成功。
- 灰蓝：普通图标和次级控件。

字体建议：

- 正文继续使用无衬线字体。
- 页面大标题可以适度使用更具人文感的中文字体，但仅限标题。
- 时间、模型名和技术参数可以使用等宽字体。
- 取消大部分英文全大写和过宽字距。

## 8. 可访问性和交互反馈

所有菜单和展开控件应统一满足：

- 使用 `aria-expanded` 表达打开状态。
- 使用 `aria-controls` 关联弹层内容。
- 使用 `aria-haspopup` 表达菜单或列表类型。
- 打开弹层后支持方向键移动。
- Enter 或 Space 选择当前项。
- Esc 关闭并将焦点归还触发器。
- 点击外部关闭。
- 焦点环在夜间模式下保持清晰。
- 尊重 `prefers-reduced-motion`。
- 图标按钮提供 `aria-label` 和 Tooltip。
- 主要点击区域不小于 32px，移动端不小于 44px。

## 9. 推荐实施顺序

### 第一阶段：解决明显不一致

1. 创建统一 `Select`。
2. 替换全部 6 个原生 `<select>`。
3. 统一圆角 Token 和 Tailwind 配置。
4. 统一展开按钮、箭头和弹层状态。
5. 修复文档页和学习目标页的中等宽度换行。

### 第二阶段：降低 AI 模板感

1. 移除重复英文眉题。
2. 减少嵌套卡片。
3. 重做各页面空状态。
4. 删除统计卡和复习 Hero 中的装饰圆。
5. 降低紫色图标容器的使用频率。

### 第三阶段：提升产品辨识度

1. 为“知屿”建立唯一的航线或岛屿视觉元素。
2. 重构 AI 输入工具栏。
3. 为文档、复习和 Agent 建立不同但一致的页面结构。
4. 完整检查键盘导航、移动端和减少动效模式。

## 10. 最高优先级

最优先处理以下三项：

1. 原生下拉菜单。
2. 圆角系统。
3. 文档页工具栏响应式布局。

完成这三项后，界面会从“局部精致但不统一”明显提升到产品级的一致性。
