# 构建与发布指南

## 本地验证

发布前至少执行：

```bash
npm ci
npm test
npm run build
```

## Windows

本地需要 Node.js 24。执行：

```powershell
npm run exe
```

脚本会生成图标、构建 Electron 前端，并把安装程序、blockmap 和 `latest.yml` 复制到 `release/`。本地下载 Electron 依赖时使用国内镜像，GitHub Actions 使用官方源。

## Android

本地需要 JDK 21、Android SDK，并设置 `ANDROID_HOME` 或 `ANDROID_SDK_ROOT`：

```powershell
npm run apk
```

本地无 Android 环境时不要配置应用同步 Token 来代替发布凭据；直接推送版本标签，由 GitHub Actions 在隔离环境中构建并签名。

## 发布新版本

1. 更新 `package.json`、lockfile、Android `versionName/versionCode` 和 `CHANGELOG.md`。
2. 完成测试与多目标构建。
3. 提交全部版本变更。
4. 创建并推送语义化版本标签：

```bash
git tag -a v1.5.0 -m "知屿 v1.5.0"
git push origin knowledge-base
git push origin v1.5.0
```

标签会同时触发 Windows 和 Android 工作流。它们将安装包、更新元数据、blockmap 和签名 APK 上传到同一个 GitHub Release。发布状态与产物以仓库的 Actions 和 Releases 页面为准。

不要把用户 AI Key、GitHub 同步 Token 或 Android 签名材料写入代码、`VITE_*` 变量或构建产物。Android 签名只使用仓库 Actions Secrets。
