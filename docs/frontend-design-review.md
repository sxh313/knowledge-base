# 知屿前端设计评审与优化实施方案

> 目标：把“知屿”从一个像飞书 / Notion 的通用知识库，升级成一个有学习陪伴感、知识沉淀感、AI 训练感的个人学习工作台。

## 一、总体判断

当前 app 最大的问题不是“丑”，而是视觉身份还没有成立。

它现在更像一个功能很多、工程完成度不错的工作台：文档、AI、面试训练、学习目标、统计、标签、设置都已经具备。但视觉语言偏通用，明显向飞书、Notion、ChatGPT、后台管理系统靠拢，没有真正把“知屿”这个名字设计出来。

一句话毒评：

> 现在的 UI 像一个认真写完需求清单的工程师产品，功能在，但气质还没出生。下一步不是继续加组件，而是给“知屿”立一套自己的视觉人格。

## 二、核心问题

### 1. 品牌视觉太弱

当前设计 token 里直接以“飞书式干净浅灰白”“飞书蓝”为目标，这会让产品天然长得像别人的工具。

“知屿”本身其实有很强的视觉意象：

- 岛屿
- 知识沉积
- 海图
- 航线
- 灯塔
- 学习路径
- 卡片群岛

但现在界面里几乎没有这些意象。它只是蓝色侧栏、通用卡片、通用按钮和通用暗色工作台。

### 2. AI 页面没有明确任务牵引

AI 页面是产品感最重要的页面，但现在打开后看到的是：

- 左侧空历史
- 主区域大面积空白
- 欢迎说明文字
- 底部一排参数控件
- 输入框
- 悬浮番茄钟

功能很多，但用户第一眼不知道“此刻最应该做什么”。

欢迎文案更像说明书，而不是任务入口。知识范围、RAG 模式、模型、联网、Agent 模式都堆在 composer 上方，视觉上像调试台。

### 3. 控件太多，但优先级太平

侧栏、顶栏、搜索、帮助、视图模式、同步、番茄钟、AI composer、Agent 模式都在抢注意力。

尤其 AI 页中，浮动番茄钟压在输入区右下角，会干扰输入和发送按钮区域。它是有用功能，但不应该在所有场景里都悬浮抢焦点。

### 4. Emoji 和图标语言混杂

当前 UI 中大量使用 emoji：

- 👋
- 📝
- 📘
- 🔒
- 💡
- 🤖
- 🌐
- ✅
- ⚠️
- 🔴

同时又使用 lucide 图标。两套视觉语言混用后，界面会显得不够专业，也会降低品牌一致性。

建议：

- 核心 UI 控件使用 lucide 或统一定制图标。
- 模板内容、正文内容、学习笔记里可以保留 emoji。
- 状态提示可以少量使用 emoji，但不要作为核心导航或控件图标。

### 5. 圆角、阴影、玻璃态过多

当前很多区域都有大圆角、阴影、玻璃态、hover 上浮。结果是所有东西都像浮起来的卡片，但真正的视觉层级反而不清晰。

工作台类应用应该更克制：

- 大面积容器少用卡片感。
- 阴影主要用于浮层、弹窗、composer。
- 普通内容卡片用细边框即可。
- hover 不要所有按钮都上浮。

### 6. Loading 状态过于贫血

当前懒加载状态只有“加载中…”。在暗色窄屏下，它会接近黑屏体验。

这对一个本地优先知识应用来说不够可靠。用户不知道是加载慢、数据迁移、代码异常，还是应用卡住。

### 7. 信息架构像功能清单，不像用户路径

当前导航把“文档 / 收集箱 / 知屿 AI / 面试训练营 / 学习目标 / 统计 / 标签 / 设置”平铺在同一级。

问题是：这些入口不是同一层级的东西。

- 文档、收集箱、AI、训练营是高频工作入口。
- 学习目标、统计是学习反馈入口。
- 标签是管理入口。
- 设置是系统入口。

现在全部平铺，会让产品像“功能菜单”，而不是“学习路径”。

建议按用户心智重新分组：

```text
创作
  文档
  收集箱

智能
  知屿 AI
  面试训练营

成长
  学习目标
  统计

管理
  标签
  设置
```

移动端则更应该只暴露高频入口，不要把低频入口塞进底部导航。

### 8. 主操作不够唯一

很多页面同时出现多个看似同等级的操作。

例如文档页顶部：

- 多选
- 今日笔记
- 模板
- 排序
- 新建

这些控件视觉权重接近，但真正主操作只有“新建 / 搜索 / 打开文档”。

建议原则：

- 每个页面只能有一个最强主按钮。
- 低频操作移入菜单。
- 排序、筛选、模板、批量操作不要和主按钮同级。
- 危险操作不要出现在默认工具栏里抢视线。

### 9. 文案偏开发者说明，不像产品语言

当前有些文案解释的是系统能力，而不是用户任务。

例如：

```text
可以在输入框上方选择「自己的文档」「面试题库」「完整课程」或「全部知识库」，回答会附带可定位的来源。
```

这句话准确，但像功能说明。更好的方式是变成任务入口：

```text
问你的笔记、练一道面试题，或把答案整理成可复习文档。
```

文案优化原则：

- 少解释系统结构，多描述用户能完成什么。
- 按动作命名按钮，不按实现命名。
- 错误提示必须告诉用户怎么修。
- 空状态必须给下一步。
- 成功提示要和按钮动词保持一致。

### 10. 信息密度断层明显

有些区域很空，例如 AI 欢迎页；有些区域又很挤，例如 composer 控件、编辑器 toolbar、移动端更多菜单。

这会造成两个问题：

- 空的地方显得产品没内容。
- 挤的地方显得产品难学。

建议：

- 空态用任务入口填充，而不是长说明。
- 工具栏按使用频率折叠。
- 高级能力默认隐藏。
- 列表页保持稳定密度。
- 工作区页面保留大面积留白，但必须有明确焦点。

### 11. 可访问性还不够系统

当前已经有一些 `aria-label` 和 `title`，但还不够完整。

重点问题：

- 很多 icon-only 按钮只靠 `title`，键盘和读屏体验不稳定。
- 拖拽排序缺少键盘替代路径。
- 颜色承担了太多状态表达，例如 active、danger、success。
- 移动端 bottom sheet 打开后，需要更明确的焦点管理。
- modal / sheet 需要 Esc 关闭、焦点陷阱、关闭后回到触发按钮。

建议：

- 所有 icon-only button 必须有 `aria-label`。
- 拖拽排序同时提供上移 / 下移按钮。
- 状态变化不要只靠颜色，也要有文本或图标。
- modal / sheet 增加焦点管理。
- 检查键盘 Tab 顺序。
- 检查深色模式对比度。

### 12. 深色模式不是“反色”，需要重新设计层级

当前深色模式整体可用，但层级比较闷，很多区域都是接近的深灰蓝。暗色界面如果只靠边框区分，很容易糊在一起。

建议：

- 背景、侧栏、主内容、浮层至少有 3 个稳定亮度层级。
- 主内容区不要和侧栏同亮度。
- 输入框边框在暗色下要更清楚。
- active 状态不要只靠蓝底，还要有位置指示。
- 阴影在暗色下可以少用，更多靠描边和亮度层级。

### 13. 编辑器工具栏像“功能全家桶”

编辑器工具栏里功能很多，但如果所有按钮长期可见，会让写作体验被工具感压住。

建议按频率分层：

- 高频：加粗、斜体、标题、列表、代码、链接。
- 中频：表格、图片、callout、模板。
- 低频：导出、查找替换、更多格式。

可以改成：

```text
基础格式区 | 插入区 | 更多
```

移动端编辑器工具栏尤其要收敛，否则横向滚动会让用户迷路。

### 14. 右键菜单、弹窗、抽屉缺少统一空间规则

当前 ContextMenu、TemplatePicker、ShortcutsModal、SearchReplaceBar、AI scope menu、移动端 sheet 都有自己的圆角、阴影、间距。

这些组件看起来都还可以，但合在一起不像同一个系统。

建议统一浮层规范：

- menu：8px 圆角，4px padding，轻阴影。
- popover：12px 圆角，8px padding，中阴影。
- modal：16px 圆角，顶部标题栏固定。
- sheet：移动端顶部 16px 圆角，底部 safe-area。
- 所有浮层入场动画统一为 fade + 4px 位移。

### 15. 搜索体验没有被产品化

搜索是知识库的核心能力，但现在更像工具按钮。

建议把搜索升级成产品级体验：

- 全局搜索打开后默认展示最近打开、最近编辑、常用命令。
- 搜索结果按类型分组：文档、标题、标签、AI 对话、课程。
- 命中关键词高亮。
- 空结果给建议：清除筛选、换关键词、问 AI。
- 搜索结果可以一键进入“让 AI 基于这些结果回答”。

这会明显增强“知识工作台”的高级感。

### 16. AI 引用来源应该是产品亮点，但现在只是附属信息

知屿的差异点之一是回答可溯源。现在引用来源的视觉权重偏低，只像回答后的附录。

建议：

- 引用来源用稳定编号，如 `[1] [2] [3]`。
- 回答正文中的引用和下方来源卡片互相高亮。
- hover 引用时显示来源预览。
- 点击来源时打开侧边预览，而不是打断主对话。
- 来源可信度、来源类型、命中片段要更清晰。

这应该成为 AI 页的核心特色，而不是“回答下面的一个列表”。

### 17. 学习目标和统计应该形成闭环

学习目标、统计、训练营现在更像三个页面，而不是一个学习系统。

建议建立闭环：

```text
学习目标 → 今日任务 → 训练 / 写笔记 → 掌握度变化 → 统计复盘 → 调整目标
```

UI 上可以体现为：

- 目标页面显示最近训练入口。
- 统计页能回跳到薄弱主题。
- 训练营完成后更新目标进度。
- 文档页能显示某篇笔记关联的目标。

### 18. 缺少“第一次使用”的完整引导

当前 onboarding 只是提醒配置 AI API，但新用户更需要知道第一条路径。

建议第一次使用流程：

1. 创建第一篇笔记。
2. 选择是否配置 AI。
3. 试一次“问我的文档”。
4. 生成一个学习目标或训练计划。

不要一上来就让用户配置模型。对大多数用户来说，“先看到价值”比“先完成设置”重要。

### 19. 错误状态缺少可恢复设计

很多错误提示只是显示错误文本。真正好的错误状态应该回答：

- 发生了什么？
- 影响什么？
- 用户能做什么？
- 是否可以重试？

建议错误组件统一：

```text
标题：同步失败
说明：本地内容已保存，但没有同步到远端。
操作：重试 / 查看设置
```

AI 调用失败：

```text
回答生成失败
可能是模型配置或网络问题。你的问题已保留，可以重试。
重试 / 检查模型设置
```

### 20. 设计系统缺少“反例规范”

现在的问题不是没有组件，而是没有规定“不应该怎么用”。

建议在设计文档里明确禁止项：

- 不要在核心 UI 里使用 emoji 作为图标。
- 不要在页面大区域里嵌套卡片。
- 不要让每个 hover 都上浮。
- 不要一个页面出现多个强主按钮。
- 不要用颜色作为唯一状态表达。
- 不要让高级设置默认占据主路径。
- 不要用长说明文案填补空态。

## 三、设计方向

建议把“知屿”的视觉方向定为：

> 知识岛屿 / 海图 / 沉积层 / 灯塔感。

这不是要在界面里画海浪，而是把这些意象转译为 UI 规则。

### 1. 色彩

不要继续使用“飞书蓝”作为主色。可以转向更有识别度的海图蓝、潮汐青、灯塔暖光。

建议浅色 token：

```css
--color-bg: #f4f7f8;
--color-surface: #ffffff;
--color-surface-2: #eef3f4;
--color-text: #172326;
--color-text-secondary: #5c686b;
--color-text-tertiary: #8a9699;
--color-primary: #167c8c;
--color-primary-hover: #0f6673;
--color-primary-light: #e3f4f6;
--color-accent: #f0a84b;
--color-accent-hover: #d88d31;
--color-accent-light: #fff3df;
--color-border: #d9e2e4;
--color-border-strong: #c2cfd2;
```

建议暗色 token：

```css
--color-bg: #0f171b;
--color-surface: #151f24;
--color-surface-2: #1c2a30;
--color-text: #e7edef;
--color-text-secondary: #9aa8ad;
--color-text-tertiary: #6f7e83;
--color-primary: #55c4d1;
--color-primary-hover: #7ad8e2;
--color-primary-light: #173a42;
--color-accent: #ffc46b;
--color-accent-light: #47351a;
--color-border: #2a3a40;
--color-border-strong: #3a4c53;
```

### 2. Typography

当前字体偏系统默认，没问题，但没有个性。

建议：

- 正文继续用系统中文字体，保证阅读体验。
- 页面大标题可以略微加强字重和字距，不要过度营销化。
- 数据、时间、进度、模型名等使用 `tabular-nums` 或 utility face。
- AI 回答正文保持舒适行距，不要被工具栏视觉噪音打断。

### 3. 结构

页面应该像“地图”：

- 左侧是导航和知识路径。
- 主区域是当前正在探索的岛屿。
- 右侧或底部是证据、计划、掌握度、上下文。

不要每个页面都堆卡片。页面大结构应该更稳定，卡片只用于可重复条目、浮层、工具块。

### 4. Signature Element

建议给知屿一个可复用的视觉记忆点：

> “知识海图线”：一种非常克制的细线 / 点阵 / 路径样式，用于学习路径、训练进度、文档关系、AI 引用来源。

它可以出现在：

- 面试训练营进度
- 文档知识图谱
- AI 来源引用
- 学习目标路径
- 空态插图

这比单纯换颜色更容易建立产品识别度。

## 四、实施阶段

### 阶段 1：重建视觉 Token

目标：先让产品不再像飞书皮肤。

主要动作：

1. 替换全局色彩 token。
2. 删除或改写“飞书式”相关注释和设计锚点。
3. 统一圆角系统。
4. 降低阴影强度。
5. 限制玻璃态使用范围。
6. 去掉全局按钮 hover 上浮，避免所有控件都在动。

建议圆角规范：

```css
--radius-sm: 4px;
--radius-md: 8px;
--radius-lg: 12px;
--radius-xl: 16px;
```

使用规则：

- 普通按钮：8px
- 普通卡片：8px
- 输入框：8px
- composer：12-14px
- modal：12-16px
- 移动端 bottom sheet：16px 顶部圆角

涉及文件：

- `src/styles/globals.css`
- `tailwind.config.js`

### 阶段 2：优化全局外壳

目标：降低外壳噪音，让页面主任务成为焦点。

#### 侧栏

当前侧栏可用，但偏厚重。建议：

- nav item 高度统一为 36px。
- icon 统一为 18px。
- active 状态使用浅底 + 主色文字 + 左侧 3px 指示线。
- 不要 active 后又蓝底又右侧小圆点，选择一种表达即可。
- 品牌区强化“知屿”身份，可以使用更独特的 logo 容器或海图点线。

#### 顶栏

当前顶栏控件过多。建议：

- 时间保留，但视觉降级。
- 视图模式放入设置或仅开发模式显示。
- 同步状态只在同步中、失败、成功短暂反馈时出现。
- 帮助入口保留。
- 番茄钟不要默认悬浮遮挡主内容。

#### 番茄钟

建议三种状态：

- 默认收起到顶栏右侧，只显示 `25:00`。
- 用户点击后展开小面板。
- 移动端收进“更多”或顶栏，不覆盖 composer。

涉及文件：

- `src/components/Layout.tsx`
- `src/components/PomodoroWidget.tsx`

### 阶段 3：重做 Loading 和 Empty State

目标：让应用启动、空数据、失败状态都显得可靠。

#### 全局 Loading

替换当前简单 fallback：

```tsx
<div className="flex items-center justify-center h-screen text-gray-400">
  加载中…
</div>
```

建议做 `AppLoadingState`：

- 显示知屿 logo。
- 文案：`正在打开你的知识库`
- 2 秒后显示次级提示：`如果一直停留，可以刷新重试`
- 使用轻微 skeleton 或脉冲点。
- 暗色 / 浅色都适配。

涉及文件：

- `src/App.tsx`

#### 空状态

空状态不要只是“没有数据”，而要给下一步。

文档空态：

- 标题：`从第一块知识开始沉积`
- 文案：`写一篇笔记，或导入 Markdown，把零散学习变成可搜索、可复习的知识岛。`
- 主按钮：`写第一篇文档`
- 次按钮：`导入 Markdown`
- 小链接：`配置 AI`

AI 空态：

- 不要长说明。
- 改成 3 个任务入口。

训练营空态：

- 没有今日计划时，主按钮应该是 `生成今日计划`。

### 阶段 4：优先重做 AI 页面

AI 页面是最应该优先优化的地方，因为它最能决定产品质感。

#### 当前问题

- 欢迎区像说明书。
- composer 上方控件太多。
- 左侧空历史占大空间。
- Agent 模式和普通对话关系不清晰。
- 番茄钟遮挡输入区域。

#### 新布局建议


### 阶段 9：动效与交互反馈规范

目标：让动画帮助用户理解“我刚才做了什么、系统正在做什么、接下来该看哪里”，而不是为了动而动。

当前 app 不是缺动画，而是动画没有叙事。按钮会动、卡片会上浮、面板会淡入，但这些动效没有稳定地服务操作反馈。

#### 1. 点击反馈

当前全局按钮 hover / active 都有 `translateY`，这会让应用有一点网页模板味。工作台应用的点击反馈应该更稳。

建议：

- 普通按钮：点击时轻微压下 `scale(0.98)`，hover 不上浮。
- 主按钮：点击后可以有一圈很轻的 focus / ripple。
- 图标按钮：hover 只变背景色，不移动。
- 危险按钮：hover 加深红色，不做弹跳感。
- 禁用按钮：不要有 hover / active 动效。

建议样式方向：

```css
button:hover {
  transform: none;
}

.btn-primary:active {
  transform: scale(0.98);
}

.icon-button:hover {
  background: var(--color-surface-2);
}
```

#### 2. 页面切换

当前路由切换统一使用 `animate-slide-up`。所有页面都从下往上飘，久了会像 PPT。

建议：

- 一级模块切换：轻微 fade + 4px 位移，120-180ms。
- 同模块内详情切换：内容交叉淡入，不改变页面大框架。
- 编辑器、AI、训练营这种工作区：不要整页动画，只让内容区域更新。

推荐样式：

```css
.page-enter {
  animation: page-enter 160ms ease-out both;
}

@keyframes page-enter {
  from {
    opacity: 0;
    transform: translateY(4px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}
```

#### 3. AI 对话动效

AI 页最适合做细腻动效，但不能花哨。

建议：

- 用户消息发送后：输入框内容快速收起，消息 bubble 从底部 6px 淡入。
- AI 思考中：不要只用三个灰点，可以做“检索 → 整理 → 生成”的状态反馈。
- 引用来源出现：回答完成后，来源卡片从下方轻轻出现。
- 保存为文档：按钮变成 `已保存`，同时出现轻量 toast。
- 流式输出光标：当前蓝色竖条略突兀，可以换成更细的主色 caret。

状态文案建议：

```text
正在检索你的文档…
正在整理来源…
正在生成回答…
```

这会比单纯 bouncing dots 更有学习助手感。

#### 4. 面试训练营动效

训练营页面不需要炫，但需要让用户感到“掌握度在变化”。

建议：

- 今日进度条：宽度变化使用 300ms ease-out。
- 完成任务：任务行先主色轻闪，再进入 done 状态。
- 掌握度变化：百分比数字从旧值平滑滚到新值。
- 诊断题评分后：正确 / 部分正确 / 薄弱使用不同微反馈。
- 下一题出现：问题卡片轻微横向进入，表达训练流程推进。

示例：

```css
.review-task-complete {
  animation: task-complete 420ms ease-out both;
}

@keyframes task-complete {
  0% {
    background: var(--color-primary-light);
    transform: scale(1);
  }
  45% {
    background: var(--color-accent-light);
    transform: scale(1.01);
  }
  100% {
    background: transparent;
    transform: scale(1);
  }
}
```

#### 5. 文档编辑反馈

本地优先笔记应用最重要的是让用户相信“我写的东西保存了”。

建议：

- 自动保存状态使用小状态点。
- 正在保存：状态点轻微 pulse。
- 已保存：状态点变绿色，1 秒后降级为灰色。
- 保存失败：状态点变红，并显示重试入口。
- 新建文档：标题区域淡入并自动 focus。
- 插入图片 / 表格 / callout：插入块短暂高亮 600ms。
- 拖拽导入 Markdown：遮罩边框可以轻微脉冲，但不要大幅动画。
- 删除 / 移动文档：列表项先收缩淡出，再从列表移除。

#### 6. 全局 Toast

当前不同功能的反馈样式不够统一。建议建立统一 toast 系统。

toast 类型：

- success：保存成功、导入完成、复制成功。
- warning：部分失败、需要配置。
- error：保存失败、同步失败、AI 调用失败。
- info：同步中、正在处理。

toast 入场：

- 从右下或底部中间轻微上移 6px。
- 160ms fade in。

toast 退场：

- 120ms fade out。
- 不要突然消失。

#### 7. 动效原则

- 大多数动画时长控制在 120-220ms。
- 复杂反馈可使用 300-450ms。
- 位移控制在 2-8px。
- 缩放控制在 0.98-1.01。
- 工作台应用优先使用 opacity、background-color、box-shadow、transform。
- 不要动画 width / height，除非是明确的进度条。
- 不要让布局因为动画抖动。
- 尊重 `prefers-reduced-motion`。
- 动画不要替代可见状态，动效结束后状态仍然要清楚。

#### 8. 最推荐优先做的微交互

1. 去掉全局 hover 上浮，只保留点击压下。
2. AI 发送消息后 bubble 入场 + composer 回弹。
3. AI 回答生成状态改成“检索 / 整理 / 生成”分阶段。
4. 文档保存状态点。
5. 训练营任务完成反馈。
6. 全局 toast 系统统一样式和入退场动画。

## 八、逐项详细优化卡

这一章把前面的判断翻译成可以直接分配给前端、设计和产品的实施任务。每项都必须同时完成视觉、交互、文案和状态验收；只改颜色、不改任务路径，不能算完成。

### 1. 品牌视觉：让“知屿”被一眼认出来

#### 要解决的问题

现在的蓝色、卡片、侧栏和圆角组合可以属于任何知识库产品。用户记住的是“一个工具”，不是“知屿”。

#### 具体改法

- 把主色从通用蓝改成潮汐青，灯塔暖橙只用于关键提醒、完成反馈和少量重点数据。
- Logo 区增加“海图点线”细节，但控制在一个位置，不能让整站变成插画主题。
- 在目标路径、训练进度、引用来源中复用同一套点线/节点视觉，形成品牌签名。
- 统一品牌词汇：知识沉积、今日航线、继续探索、来源证据、已靠岸等可以少量出现在空态和反馈中；按钮仍使用清晰动作词。
- 建立品牌禁用项：不能同时使用蓝紫渐变、玻璃卡片、emoji 导航、夸张发光和多套插画风格。

#### 实施顺序

1. 先在 `tokens.css` 建立颜色、边框、状态和品牌装饰 token。
2. 在 Layout 品牌区做一个静态 Logo 版本，确认尺寸、明暗主题和缩窄侧栏表现。
3. 把品牌签名应用到一个高价值场景，优先选择 AI 引用或训练进度。
4. 截图对比：如果去掉 Logo 后页面仍无法区分知屿，说明品牌元素还不够明确；如果每处都有装饰，说明使用过量。

#### 验收标准

- 首屏不依赖标题文字也能感受到统一的品牌语言。
- 品牌装饰不影响文本阅读、点击区域和加载性能。
- 浅色、暗色、窄侧栏、移动端均有同一套签名元素。

### 2. AI 页面：从“模型调试台”变成任务入口

#### 要解决的问题

用户进入 AI 页后面对的是配置项，而不是下一步。参数越多，越像开发工具；任务入口越弱，越难体现 AI 的价值。

#### 具体改法

- 空态只保留三个任务卡，每张卡包含动作标题、结果描述和一条示例问题。
- 任务卡点击后直接填入 composer，不要立刻自动发送，让用户保留编辑权。
- 当前知识范围显示为一个可识别的 chip，点击后打开范围选择器；默认范围记住用户上次选择。
- 模型、联网、Agent、检索策略全部收进“回答设置”，并显示当前启用摘要。
- 流式回答时固定消息布局，避免引用出现导致整个页面跳动。
- AI 回复底部固定放置“继续追问 / 保存为文档 / 查看来源”三个动作，其他动作进入更多菜单。
- 长回答提供折叠、复制、重新生成和引用跳转，不能让用户一直滚到底部找操作。

#### 交互状态

```text
空闲 → 已输入 → 检索中 → 整理来源 → 生成中 → 已完成
                         ↘ 失败：重试 / 检查设置
```

每个状态都需要有可见文本、按钮可用性和取消路径。生成中允许停止生成；失败保留原问题和已生成内容。

#### 验收标准

- 新用户 5 秒内能理解 AI 可以做什么。
- 默认状态不超过一个主按钮和三个次级入口。
- 发送、停止、重试、保存、引用预览均可在键盘和移动端完成。
- AI 生成过程页面不闪烁、不跳布局、不遮挡 composer。

### 3. 控件层级：建立“一个页面一个主任务”

#### 具体改法

- 页面标题区只保留标题、必要上下文和一个主按钮。
- 排序、筛选、导入、批量操作统一放入工具组或更多菜单。
- 主按钮采用实心潮汐青；次按钮使用描边或文本样式；危险按钮只在确认上下文出现。
- 用尺寸、位置和文案建立层级，不要同时靠鲜艳颜色、阴影、动画抢注意力。
- 给按钮定义 `primary / secondary / tertiary / danger / icon` 五种角色，禁止组件调用者自行拼颜色。

#### 验收标准

- 每个主要页面视线追踪时，第一落点是页面主任务。
- 低频功能仍可找到，但不会和主按钮竞争。
- 任何页面不出现两个同等级实心主按钮。

### 4. 图标系统：去掉视觉噪声

#### 具体改法

- 核心导航、操作、状态统一使用 Lucide，统一 `18px` 默认尺寸和 `1.8px` 线宽。
- Emoji 只允许出现在用户内容、模板内容或明确的装饰性空态中。
- 建立 `iconMap.ts`，集中维护“功能 → 图标”的映射，避免每个页面自行选择。
- icon-only 控件必须有 `aria-label`、`title` 和可见 focus ring。
- 不用图标表达无法理解的专业概念；首次出现的特殊状态必须带文字。

#### 验收标准

- 同一功能在所有页面使用同一图标。
- 线性图标、填充图标、emoji 不在同一控件组中混用。
- 关闭图标、更多图标、搜索图标等基础操作无需猜测。

### 5. 容器和层级：减少“卡片套卡片”

#### 具体改法

- 页面背景、工作区、浮层使用三层 surface；普通列表项不再额外套厚重卡片。
- 卡片只承载可独立比较、移动或操作的内容。
- 默认阴影只用于 popover、modal、composer；列表和页面区块优先使用边框及间距区分。
- hover 只改变背景或边框，只有可拖拽、可进入的对象才允许轻微位移。
- 规定嵌套上限：页面区块内最多一层卡片，卡片内不再套同类卡片。

#### 验收标准

- 首屏能分辨页面背景、内容区和浮层，不需要依靠大量阴影。
- 关闭阴影后信息层级仍成立。
- 长列表滚动时没有“卡片墙”造成的视觉疲劳。

### 6. Loading、空态和错误：让系统状态可理解

#### 具体改法

- Loading 分为应用启动、页面数据、局部操作三类，不能使用同一个全屏文案。
- 页面数据加载使用与最终布局相似的 skeleton，避免内容出现时跳动。
- 空态必须包含“原因/价值/下一步”三部分；最多一个主 CTA。
- 错误必须显示影响范围、恢复动作和是否保留本地内容。
- 所有可重试操作提供按钮 loading、失败后的重试次数和不会重复提交的保护。

#### 验收标准

- 网络慢、数据库为空、API 未配置、请求失败四种情况文案不同。
- 用户能判断内容是否已保存、是否需要重试、重试会不会丢数据。
- 空态不使用长段落替代操作入口。

### 7. 信息架构：按学习路径组织，而不是按开发模块组织

#### 具体改法

- 桌面侧栏按“创作 / 智能 / 成长 / 管理”分组，并允许分组折叠。
- 分组标题是弱层级文本，不参与抢焦点；当前页面仍通过 item 高亮表达。
- 收集箱作为“输入入口”，文档作为“沉淀入口”，AI 作为“探索入口”，训练营作为“验证入口”。
- 学习目标和统计之间增加回跳：薄弱主题点击后直接进入相关训练或文档。
- 移动端只把四个高频入口放在底部，低频入口进入分组后的更多页。

#### 验收标准

- 用户能回答“我从哪里开始写、从哪里复习、从哪里看进步”。
- 新增功能必须先归属一个用户路径，再决定是否放进侧栏。
- 桌面和移动端导航的名称、顺序、当前态保持一致。

### 8. 文档首页：让第一篇知识顺利落地

#### 具体改法

- 有文档时首屏优先显示最近编辑和继续编辑，不让收藏、统计、模板抢主位。
- 无文档时只展示“写第一篇文档”和“导入 Markdown”两个动作，AI 配置放次级区域。
- 文档条目显示标题、更新时间、关联目标或标签，摘要只在有价值时显示。
- 列表 hover 显示操作，默认不堆满复制、移动、删除、分享等图标。
- 新建成功后直接进入编辑器，标题自动聚焦，保存状态在标题区可见。

#### 验收标准

- 从空库到开始输入不超过两次点击。
- 从最近文档到继续编辑不需要先打开多余详情页。
- 长标题、无摘要、多个标签、删除确认都不破坏列表布局。

### 9. 训练营：把页面变成“今日训练驾驶舱”

#### 具体改法

- 顶部只显示今日完成度、剩余时间、当前阶段和继续训练按钮。
- 当前题目/回答区占最大面积；计划、掌握度和来源作为辅助栏。
- 题目状态明确区分未开始、进行中、待复盘、已掌握，不只用颜色。
- 完成一题后展示“答案诊断 → 薄弱点 → 下一题”连续路径。
- 没有计划时，解释生成计划会基于哪些数据，并提供可编辑的时间预算。
- 训练完成页必须给可操作的下一步：复习薄弱点、查看来源、调整明日计划。

#### 验收标准

- 页面打开后用户能立刻知道今日第一题和下一步动作。
- 掌握度变化与具体题目、文档或目标有关联。
- 完成训练后不是只显示“成功”，而是给出复盘入口。

### 10. 编辑器：让写作优先于工具栏

#### 具体改法

- 桌面端保留高频格式操作，低频操作放“插入”和“更多”。
- 移动端 toolbar 使用分组横向滚动，但默认露出加粗、标题、列表、链接四项。
- 编辑区限制合理阅读宽度，标题、正文、代码块和 callout 有稳定垂直节奏。
- 自动保存状态靠近标题显示，不能藏在全局顶栏。
- 粘贴、拖拽、插入失败时保留用户原内容并提供重试。
- 删除文档前明确说明是否可在回收站恢复，危险动作不要使用模糊的“确定”。

#### 验收标准

- 编辑器在无工具栏状态下仍可完成连续写作。
- 输入、保存、插入块、撤销、重做、离开页面均不会丢失内容。
- 移动端键盘弹出时，当前光标和保存状态仍可见。

### 11. 移动端：重新设计触摸工作流

#### 具体改法

- 所有核心触控目标至少 `44px`，图标和文字不能挤在同一 32px 区域。
- composer 使用底部安全区 padding，键盘出现时避免固定层覆盖输入内容。
- AI 历史记录改为顶部抽屉；文档树改为侧滑抽屉；复杂设置用 bottom sheet。
- FAB 只有在不与底部导航、键盘和 toast 冲突时才显示。
- 长列表保留清晰的返回、标题和当前上下文，不让用户迷失在抽屉层级里。

#### 验收标准

- 390×844 下核心路径无需横向滚动。
- 键盘弹出、旋转屏幕、打开 sheet、返回页面时布局不跳坏。
- 所有浮层有明显关闭方式，并支持返回手势或系统返回。

### 12. 动效：用状态变化建立信任

#### 具体改法

- 动效只服务四类反馈：进入、进行中、完成、失败。
- 点击使用压下而非上浮；页面切换使用 4px 内的淡入；工作区不做整页飘入。
- AI 状态采用“检索 / 整理 / 生成”，训练采用“答题 / 诊断 / 下一题”，保存采用“保存中 / 已保存 / 保存失败”。
- 重要反馈的最终状态必须静态保留，不能动画结束后什么都没有。
- 统一动画 token：`--duration-fast: 120ms`、`--duration-normal: 180ms`、`--duration-emphasis: 360ms`。
- 所有动画在 `prefers-reduced-motion: reduce` 下改为即时切换或极短淡入。

#### 验收标准

- 用户能从动效判断刚刚发生的动作。
- 任何动画不遮挡输入、按钮或阅读内容。
- 低性能设备上不出现明显掉帧和布局抖动。

### 13. 搜索与 AI 引用：构建“可追溯知识”优势

#### 具体改法

- 全局搜索支持快捷键打开、最近记录、分组结果、关键词高亮和键盘上下选择。
- 搜索结果展示结果类型、所在位置、更新时间；点击后保留返回搜索结果的路径。
- “基于结果询问 AI”把当前结果集作为明确上下文，并在 composer 显示来源数量。
- 引用编号使用稳定 ID；正文编号和来源卡片 hover/click 双向联动。
- 来源侧栏显示标题、命中片段、所在段落、更新时间，并提供打开原文和复制引用。
- 引用加载失败时保留编号和“来源暂不可用”，不要让回答结构塌掉。

#### 验收标准

- 用户能从一次回答回到原文准确位置。
- 搜索没有结果时仍有明确下一步。
- 引用不会遮挡回答，也不会打开后丢失当前对话上下文。

### 14. 可访问性与浮层：补齐真实可用性

#### 具体改法

- 为主要区域补充 `header / nav / main / aside` landmark，标题层级按页面结构递进。
- icon-only button、状态点、拖拽目标、关闭动作均有可读名称。
- modal 和 sheet 打开时锁定背景滚动，焦点进入首个可操作元素；关闭后回到触发按钮。
- 下拉菜单使用方向键，Esc 关闭；搜索结果支持上下键和 Enter。
- 拖拽排序同时提供上移、下移和移动到分组操作。
- 颜色状态增加文字、图标或形状，焦点环不能被 `outline: none` 删除。

#### 验收标准

- 仅用键盘可以完成“搜索 → 打开文档 → 编辑 → 保存 → 返回”。
- 读屏能知道按钮用途、当前状态和错误原因。
- 200% 浏览器缩放和窄屏下内容仍可操作。

## 十、建议的执行看板字段

为了避免 Todo 变成愿望清单，每一项任务建议使用以下字段记录：

| 字段 | 要求 |
| --- | --- |
| 任务 | 用动作开头，例如“重做 AI 空态任务卡” |
| 优先级 | P0 / P1 / P2；P0 阻塞主路径，P1 提升核心体验，P2 为收口项 |
| 页面/文件 | 写明页面、组件或样式文件 |
| 依赖 | 例如 Token 完成后才能统一组件 |
| 设计产物 | 截图、交互稿、文案表或状态图 |
| 验收状态 | 未开始 / 进行中 / 待视觉验收 / 已完成 |
| 截图链接 | 至少包含浅色桌面、暗色桌面、移动端之一 |
| 回归风险 | 记录是否影响编辑器、路由、数据保存和移动端 |

## 十一、最终优先级判断

不要先把所有页面都“美化一遍”。正确顺序是先修正产品主路径，再修饰细节：

1. 先让用户知道知屿是谁：品牌 token、外壳、导航。
2. 再让用户知道现在做什么：AI 空态、文档空态、训练营主任务。
3. 再让用户相信系统可靠：保存、加载、错误、引用和恢复。
4. 再让操作变得顺手：搜索、键盘、移动端、浮层。
5. 最后才做动效和装饰收口：只保留能解释状态的动画。

如果只能做一轮，优先完成 Todo 0、Todo 1、Todo 3、Todo 4 和 Todo 5。它们会直接改变第一印象、核心转化和产品可信度；其余任务在此基础上继续收口。
