# Agent 与编辑器表格后续优化方案

## 当前结论

当前 Agent 安全执行链路和编辑器表格基础能力已经可用，但距离稳定、透明、高效的深度使用体验，还需要补齐真实交互验证、执行过程可视化、失败恢复和大型计划审查能力。

## 1. 编辑器表格真实交互验证

### 已有能力

- 增加、删除行列。
- 合并、拆分单元格。
- 删除整张表格。
- 宽表格横向滚动。
- 长文本自动换行。

### 待验证场景

- 光标位于表格时，编辑工具是否稳定出现。
- 选择多个单元格后，“合并”是否正确启用。
- 合并后能否正确拆分。
- 删除最后一行或最后一列时，表格是否保持正常。
- 拖动列宽后，保存和刷新是否能保留列宽。
- Markdown 导入、导出后，复杂表格结构是否丢失。
- 移动端能否单独横向滑动表格，不影响页面纵向滚动。
- 工具栏在窄屏和宽表格环境下是否溢出屏幕。

### 数据格式边界

标准 Markdown 不支持合并单元格和精确列宽。若只保存 Markdown，TipTap 中的高级表格结构可能在重新加载时丢失。

可选方案：

1. 仅支持标准 Markdown 表格，优先保证兼容性。
2. 同时保存 Markdown 和编辑器 JSON；Markdown 用于导出和检索，JSON 用于还原列宽、合并状态等高级结构。

推荐采用第二种方案，但需要进行数据结构升级和兼容迁移。

## 2. Agent 实时执行状态

当前 Agent 主要显示“正在分析并生成操作计划”，复杂任务中还不够具体。

建议在主对话区展示阶段进度：

```text
1. 检索相关文档        已完成
2. 分析重复内容        已完成
3. 生成整理计划        已完成
4. 等待用户确认        当前
5. 更新文档            未开始
6. 重建索引            未开始
```

执行时显示当前操作：

```text
正在执行 3/8：为《RAG 基础》补充标签
```

### 预期收益

- 用户能判断任务是否仍在运行。
- 可以快速定位耗时或失败步骤。
- 批量任务的执行过程更可控。
- 已有运行事件和操作状态能被充分利用。

## 3. 智能失败恢复

当前“重试上个任务”会重新提交原始请求。如果失败原因未发生变化，可能重复失败。

建议根据失败类型决定恢复方式：

```text
原计划失败
  ↓
读取失败原因
  ↓
判断失败类型
  ├─ 模型超时 → 原任务重试
  ├─ 文档已变化 → 重新读取并生成新计划
  ├─ 权限不足 → 引导用户调整权限
  ├─ 操作冲突 → 移除冲突项并重新预览
  └─ 服务不可用 → 保留任务，稍后重试
```

建议提供三个操作：

- 直接重试。
- 根据错误重新规划。
- 查看失败详情。

重新规划后必须生成新计划并再次等待用户确认，不得绕过审批。

## 4. 大型计划分组审查

当前操作计划以单一列表呈现。操作超过 20 项时，用户难以快速判断影响范围。

建议按目标文档分组：

```text
《RAG 基础》                     3 项
  ✓ 添加标签                    低风险
  ✓ 补充相关链接                中风险
  □ 重写正文                    高风险

《Agent Memory》                2 项
  ✓ 修复标题                    低风险
  □ 删除重复章节                高风险
```

建议提供筛选：

- 全部。
- 低风险。
- 中风险。
- 高风险。
- 执行失败。

支持“仅执行安全项”，高风险操作必须单独确认。

## 5. 表格自动化测试

需要为富文本编辑器补充专门的表格测试：

- 插入 3×3 表格。
- 添加和删除行列。
- 合并、拆分单元格。
- 表格内使用 Tab 移动。
- 最后一个单元格按 Tab 自动增加一行。
- 输入长文本不会撑破编辑区域。
- 保存并重新加载后内容仍然存在。
- 撤销和重做表格操作。
- 删除表格后光标能回到正文。

## 6. 响应式与视觉检查

### 桌面端

- 表格编辑工具不会遮挡正文。
- 宽表格横向滚动区域清晰。
- 列宽拖动手柄容易命中。
- 选中单元格与普通单元格有明确区别。

### 移动端

- 表格能够单独横向滑动。
- 页面宽度不会被表格撑开。
- 表格操作按钮允许换行，不会挤在一行。
- 合并、删除等高影响操作不容易误触。

## 实施顺序

1. 实际测试并修复编辑器表格。
2. 添加表格自动化测试。
3. 展示 Agent 逐步骤实时进度。
4. 增加“根据错误重新规划”。
5. 对大型计划按文档和风险分组。
6. 完成桌面端和移动端视觉验证。
7. 提交并发布补丁版本。

## 验收标准

- 表格的插入、编辑、保存、重新加载和撤销均能稳定工作。
- 宽表格和长文本不会破坏编辑器布局。
- Agent 主界面能够显示当前阶段和正在执行的具体操作。
- 失败后可以直接重试、查看原因或生成新的待确认计划。
- 大型计划可以按文档和风险快速筛选、批量选择。
- 桌面端和移动端均通过实际交互检查。
