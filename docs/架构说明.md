# 架构说明

本文只描述当前代码已经实现的结构。功能行为以 `src/`、Electron/Capacitor 配置和测试为准。

## 运行形态

- Web/PWA：Vite 构建的 React 单页应用，使用 `BrowserRouter`。
- Windows：Electron 加载同一套前端产物，使用 `HashRouter`，通过 `electron-updater` 检查 GitHub Releases。
- Android：Capacitor 封装同一套前端产物，使用 `HashRouter`。

`BUILD_TARGET` 只决定路由基址和目标平台构建行为，不注入用户凭据。

## 分层

| 层 | 目录 | 职责 |
| --- | --- | --- |
| 页面 | `src/pages` | 路由级交互与页面编排 |
| UI | `src/components` | 通用组件、编辑器、同步与设置组件 |
| 状态 | `src/stores` | 页面状态、异步动作和跨组件状态 |
| 领域逻辑 | `src/lib` | AI、Agent、复习、搜索、索引、备份与同步 |
| 持久化 | `src/lib/db` | Dexie schema、迁移和领域数据访问 |
| 平台壳 | `electron`、`android` | 桌面更新、系统集成和移动封装 |

应用启动由 `src/lib/app/bootstrap.ts` 统一编排；跨页面的 AI/同步长任务使用 `src/lib/tasks/asyncTask.ts` 的统一状态；运行诊断由 `src/lib/observability/diagnostics.ts` 保存脱敏摘要。`src/lib/db/repositories/` 是页面和 store 的推荐数据访问入口，`queries.ts` 暂作为兼容门面保留。

较大的实现已按边界拆分，例如卡片、附件、分类数据访问，Agent 搜索，TipTap 代码块，设置中的同步区，以及同步记录合并。

## 本地数据

Dexie 数据库当前 schema 版本为 14。核心数据包括文档、卡片、附件、版本、分类、搜索、AI/Agent 会话与审计、同步冲突、偏好、学习目标和学习任务；zero2Review 会话、消息、掌握度、计划、任务、作答记录和学习记忆使用独立表。复习消息与作答记录带 `updatedAt/deletedAt`，可安全合并同步。

普通学习任务和 zero2Review 任务不做破坏性合表，而由 `lib/learning/taskModel.ts` 映射到统一状态、耗时、到期、逾期和完成率口径。个人文档引用同时保存内容版本哈希、字符偏移和稳定文本锚点：偏移用于兼容旧记录，锚点用于文档结构变化后的重新定位。

可同步实体使用更新时间和软删除标记。删除会先写入 tombstone，使其他设备能够收到删除操作；永久清理时仍保留必要的删除记录。

## AI 与 Agent

AI Provider 的地址、Key、启用状态和模型偏好来自当前设备设置。路由器只选择已启用且满足凭据要求的 Provider，并支持失败转移。本地 Provider 可不填 Key。

问答模式先按用户选择的知识范围检索，再把相关片段交给模型；来源包含稳定的文档/分块定位信息。Agent 模式复用模型层，但写入必须经过计划解析、风险标注、影响分析、diff 预览、用户批准和 Dexie 事务执行。运行记录支持审计与撤销。

## 同步与备份边界

GitHub 同步以一个 JSON 文件保存业务数据，按记录的更新时间和软删除状态合并；旧远端缺少新字段时使用兼容规则。冲突不会静默覆盖，而是写入冲突表供用户处理。

普通 JSON 备份和 GitHub 同步都不包含 AI Key、GitHub Token 或完整设置。密钥迁移是独立的、由主密码加密的导入导出流程。

zero2Agent 复习教练只使用 `source: zero2agent` 的固定索引来源。无关问题和模糊问题不会写入复习消息；用户提问只增加兴趣证据，只有带原文 Citation 的诊断作答才更新掌握度和 FSRS。GitHub 同步默认不上传复习问答正文，需在设置中显式开启。

## 测试重点

`npm test` 覆盖 FSRS、Markdown 往返、Agent 工具/事务/diff/质量检查、RAG 检索、同步合并和复习会话等核心逻辑。发布前还应执行 TypeScript 构建以及 Web、Electron、Android 三种目标构建。
